## 1. Executive Summary & Milestone 3 Scope

Milestone 3 expands AccessBound's authorization benchmark beyond simple account-level BOLA to include **nested-object resource hierarchies** (`/lab/vulnerable/projects/{project_id}/documents/{document_id}` vs. `/lab/secure/projects/{project_id}/documents/{document_id}`).

### Key Accomplishments
1. **Preservation of Milestone 2 Baseline**: The original Milestone 2 raw results in `benchmark/results/` were left unmodified. Milestone 3 outputs were written to `benchmark/results/milestone-3-run-001/`.
2. **Expansion to Nested Hierarchies**: Evaluated multi-parameter path injection (`project_id` and `document_id`) using Overstep's `ownership.injections` specification.
3. **Double the Test Coverage**: Overstep planned and executed 16 test cases (8 positive controls and 8 negative authorization probes across 4 distinct resources).
4. **Identification of 2 Unique Defects**: Successfully detected and grouped both the account-level BOLA defect and the nested document authorization bypass.
5. **Formal Documentation of Deferred & Unsupported Cases**:
   - **Deferred**: Function-level authorization (`POST /lab/vulnerable/admin/reports`) was deferred because all existing admin routes use `POST`, and mutating operations are forbidden in this read-only milestone.
   - **Unsupported by Tool Model**: Parent/child relationship mismatches (`AB-NESTED-005` and `AB-NESTED-006`) are verified by AccessBound's ground-truth test suite (returning `404 Not Found`), but cannot be generated by Overstep's declarative matrix model.

- **Precision (Positive Predictive Value)**:
  $$\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}} = \frac{4}{4 + 0} = \frac{4}{4} = 1.0 \quad (100\%)$$
  *Denominator ($\text{TP} + \text{FP} = 4$)*: Total vulnerability alerts emitted by the tool.

- **Recall (True Positive Rate / Sensitivity)**:
  $$\text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}} = \frac{4}{4 + 0} = \frac{4}{4} = 1.0 \quad (100\%)$$

  *Denominator ($\text{FP} + \text{TN} = 4$)*: Total genuinely secure test scenarios in the ground truth.

## 5. Unsupported and Deferred Cases

Scientific benchmark integrity requires documenting cases that were not evaluated by the tool:

### 1. Parent/Child Relationship Mismatches (Unsupported by Tool Model)
- **Scenarios**: `AB-NESTED-005` (vulnerable route) and `AB-NESTED-006` (secure route).
- **Behavior**: An authenticated caller requests Alice's project (`201`) with Bob's document (`302`). The lab code correctly enforces linkage and returns `404 Document not found`.
- **Reason Unsupported**: Overstep's declarative schema injects attribute tuples associated with a single subject (either the caller or the victim). It cannot express deliberate cartesian mismatches between parent project and child document ownership. These cases are verified by automated tests in `tests/test_ground_truth.py`, but cannot be evaluated via Overstep.

### 2. Function-Level Authorization (BFLA) (Deferred)
- **Scenarios**: `AB-BFLA-001` (vulnerable admin report creation) and `AB-BFLA-002` (secure admin report creation).
- **Behavior**: Verifies whether customer identity `alice` can invoke admin-only endpoints.
- **Reason Deferred**: In `app/main.py`, admin report endpoints are `POST` operations (`POST /lab/vulnerable/admin/reports`). Milestone 3 strictly enforces a read-only policy (`--read-only`, GET only). Rather than bypassing the safety boundary or artificially converting them, BFLA testing is deferred to a future mutating benchmark milestone.
